Agentic AI — Authenticated MCP Access

Four patterns for AI agents accessing a protected MCP server (Model Context Protocol). Three service-principal agents (UC1–UC3a) authenticate as themselves; the fourth (UC4) is delegated to by a logged-in human user and acts on their behalf with a narrower scope. All four use real MCP Streamable HTTP via the official MCP Python SDK.

{# ── Architecture summary ────────────────────────────────────────────────────── #}
How an agent run works
  1. Authenticate to Keycloak. Each agent uses its own mechanism (client secret today; SPIFFE attestation and X.509 certificate in upcoming iterations) and requests scope=mcp. Keycloak issues a JWT with aud=mcp-service and scope=mcp.
  2. Connect to the MCP server. The agent uses the official mcp Python SDK to open a Streamable HTTP session, passing the access token in Authorization: Bearer. The MCP server validates the signature, issuer, audience, expiry, and required scope, then accepts the session.
  3. Discover & call tools. The agent calls the MCP tools/list method, converts the tool schemas into Anthropic tool-use format, and hands the task to Claude. Claude returns tool_use blocks; the agent invokes them on the MCP session and feeds the results back to Claude.
  4. Return the answer. The agent records every step (token claims, MCP discovery, each loop iteration with its tool calls) and returns a single structured trace which this page renders.
Endpoints

MCP discovery /.well-known/oauth-protected-resource
MCP transport POST {{ mcp_service_url }}/mcp
