Device Authorization Grant (RFC 8628)

Enables devices with no browser or limited input — smart TVs, CLI tools, IoT sensors — to acquire OAuth2 tokens by delegating the authorization step to a secondary device (phone, laptop) that does have a browser.

{# ── LEFT — Concepts ──────────────────────────────────────────────────────── #}
How It Works
  1. Device calls /auth/device → Authorization Server returns device_code, user_code, and verification_uri.
  2. Device displays the user_code and verification_uri to the user (on screen, in terminal output, etc.).
  3. User opens the verification_uri on any capable device (phone, laptop) and enters the user_code.
  4. Device polls /token every interval seconds using grant_type=urn:ietf:params:oauth:grant-type:device_code.
  5. AS returns authorization_pending while waiting; once the user approves, it issues a full token response (access + refresh + id tokens).
POST /device/auth → device_code + user_code
→ user enters code at verification_uri
POST /token (poll every N s)
← authorization_pending (keep polling)
← access_token + refresh_token (approved!)
Use Cases

Common scenarios where Device Flow shines:

  • CLI tools — gh auth login, gcloud auth login
  • Smart TVs — streaming apps (Netflix, YouTube) on TV remotes
  • IoT devices — sensors, embedded hardware, kiosks
  • Printers / scanners — cloud-print services without full browsers

Error Codes
authorization_pending User has not yet acted — keep polling at current interval.
slow_down Polling too fast — add 5 s to interval and continue.
access_denied User actively rejected the request — stop polling.
expired_token device_code lifetime elapsed — restart the flow.

{# ── Key takeaways ─────────────────────────────────────────────────────────── #}
Key takeaways
  • The device_code is a secret never shown to the user — only the short, human-typeable user_code is displayed.
  • Polling must respect the interval field; receiving slow_down means you must add at least 5 seconds to the current interval.
  • The verification_uri_complete pre-fills the user code in the URL — useful for QR codes on TV screens.
  • Device Flow requires a confidential client in Keycloak — the client_secret is included in the polling token request.
  • RFC 8628 is widely deployed: GitHub CLI, Google Cloud SDK, AWS CLI, and Azure CLI all use this flow.
