{# ── Grant types ─────────────────────────────────────────────────────────── #}
OAuth2 Grant Types
{# Authorization Code #}
1
Authorization Code Flow
Recommended

Browser redirects to Keycloak for login. The authorization code is exchanged for tokens server-side. Supports id_token + refresh_token.

Browser → Keycloak → code → Server → tokens
Login with Authorization Code
{# Password Grant #}
2
Password Grant (ROPC)
Legacy

Credentials are sent directly to the server (no redirect). Simpler but less secure — the client app sees the password. Useful for testing.

username + password → Token Endpoint → tokens
Try Password Grant
{# Client Credentials #}
3
Client Credentials
Machine-to-Machine

No user involved. The application authenticates as itself using its client_id + client_secret. Used for microservices.

client_id + secret → Token Endpoint → access_token
Get Service Account Token
{# Advanced Token Exchange #}
Advanced Token Exchange (RFC 8693)
{# On-Behalf-Of #}
4
On-Behalf-Of (OBO)
Delegation

A middle-tier service exchanges the user's token for a new one that preserves user identity but is issued to the service itself. The downstream API still knows who the end-user is.

user_token → middle-tier → new token (same user, new azp)
{% if is_authenticated %} Try On-Behalf-Of Exchange {% else %} {% endif %}
{# Token Rescoping #}
5
Token Rescoping (Downscoping)
Least Privilege

Exchange a full token for a narrower one — the roles scope is stripped so the new token carries no realm_access.roles claim. Useful when delegating to a component that should not need admin rights.

token (admin + user) → exchange → token (no roles)
