OAuth2 Grant Types
{# Authorization Code #}
1
Authorization Code Flow
Recommended

Browser redirects to Keycloak for login. The authorization code is exchanged for tokens server-side. Supports id_token + refresh_token.

Browser → Keycloak → code → Server → tokens
Login with Authorization Code
{# Password Grant #}
2
Password Grant (ROPC)
Legacy

Credentials are sent directly to the server (no redirect). Simpler but less secure — the client app sees the password. Useful for testing.

username + password → Token Endpoint → tokens
Try Password Grant
{# Client Credentials #}
3
Client Credentials
Machine-to-Machine

No user involved. The application authenticates as itself using its client_id + client_secret. Used for microservices.

client_id + secret → Token Endpoint → access_token
Get Service Account Token

Advanced Flows
{# On-Behalf-Of #}
4
On-Behalf-Of (OBO)
Delegation

A middle-tier service exchanges the user's token for a new one that preserves user identity but is issued to the service itself. RFC 8693.

user_token → middle-tier → new token (same sub, new azp)
{% if is_authenticated %} Try OBO Exchange {% else %} {% endif %}
{# Token Rescoping #}
5
Token Rescoping
Least Privilege

Exchange a full token for a narrower one — the roles scope is stripped so the new token carries no realm_access.roles claim.

token (admin + user) → exchange → token (no roles)
{% if is_authenticated %} Try Rescoping {% else %} {% endif %}
{# SPIFFE Workload Identity #}
6
SPIFFE Workload Identity
Zero-Secret M2M

A container proves its identity to SPIRE without any stored secret. A JWT-SVID is mapped to a Keycloak service account via the SPIFFE→OAuth2 bridge.

SPIRE attests → JWT-SVID → bridge → access_token
Run SPIFFE Demo
{# DPoP — Proof of Possession #}
8
DPoP — Proof of Possession
Sender-Constrained

Cryptographically binds an access token to an EC key pair. A stolen token is useless without the matching private key. RFC 9449.

keygen → DPoP proof → token (cnf.jkt) → API proof
Run DPoP Demo
{# OIDC Identity Layer #}
7
OIDC Identity Layer
Authentication

The OpenID Connect layer on top of OAuth2: id_token, UserInfo endpoint, and Discovery document.

openid scope → id_token + UserInfo + Discovery
{% if is_authenticated %} Explore OIDC {% else %} {% endif %}
{# Device Authorization Grant #}
9
Device Authorization
RFC 8628

For CLIs, IoT devices, and smart TVs — no browser on the device. A short user_code is displayed; the user approves on a separate device. Client polls until granted.

device_code + user_code → poll → token on approval
Run Device Flow
{# PKCE #}
10
PKCE
RFC 7636

Hardens the Authorization Code flow for public clients. A code_verifier secret ties the auth code to the exact client that generated it — stolen codes are useless.

verifier → S256 challenge → code → token
Try PKCE Flow
{# Token Introspection #}
11
Token Introspection
RFC 7662

Resource servers ask the AS in real time: "is this token still valid?" Detects revocation instantly — something local JWT decode cannot do.

token → /introspect → active: true/false
Inspect a Token
