PKCE — Proof Key for Code Exchange (RFC 7636)

Binds an authorization code to a one-time secret generated by the client, so a stolen code is useless without the matching verifier. Originally required for mobile and SPA clients; now recommended for all OAuth2 flows.

{# ── LEFT — Concepts ──────────────────────────────────────────────────────── #}
Why PKCE?

Without PKCE:

An authorization code intercepted in transit (via a malicious redirect, a shared custom URI scheme, or a compromised browser) can be exchanged for tokens by anyone — the AS has no way to distinguish the legitimate client from an attacker.

With PKCE:

The client generates a code_verifier before the auth request. Only the original client — the one that knows the verifier — can complete the exchange. A stolen code without the verifier is worthless.

The Math
  1. Generate code_verifier: 32 random bytes → base64url-encode → 43-char string
  2. Compute code_challenge: BASE64URL(SHA256(code_verifier))
  3. Auth request carries: code_challenge + code_challenge_method=S256
  4. Token request carries: code_verifier — AS checks SHA256(verifier) == challenge
client generates:
verifier = base64url(random(32 bytes))
challenge = base64url(SHA256(verifier))
GET /authorize
?code_challenge=<challenge>
&code_challenge_method=S256
← 302 code=<auth_code>
POST /token
code=<auth_code>
&code_verifier=<verifier>
← access_token (if SHA256(verifier) matches)

{# ── Key takeaways ─────────────────────────────────────────────────────────── #}
Key takeaways
  • The code_verifier never travels through the browser — it stays in the client's memory and goes directly to the token endpoint over HTTPS.
  • method=S256 is the only acceptable method in production. Plain (method=plain) provides no real security and should never be used.
  • PKCE was originally designed for mobile apps (no secure secret storage) but the OAuth 2.0 Security BCP (RFC 9700) now mandates it for all authorization code flows.
  • The Keycloak client used here is a public client — no client secret is configured. PKCE is the proof of client legitimacy.
  • A new code_verifier / code_challenge pair must be generated for every authorization request — they are strictly one-time.
